# Cycle Studio 0.6 — 一軸シンプルサイクル

定常・開放シンプルサイクルの設計点計算を行う独立アプリ。Python 3.10以上の標準ライブラリだけで動作し、インストール・インターネット接続・外部CDN・アカウントは不要です。

## GitHubから取得

```powershell
git clone https://github.com/ai-infra-data-lab/gas-turbine-cycle-app.git gas_turbine_cycle_app
cd gas_turbine_cycle_app
python server.py
```

Python 3.10以上が必要です。追加Pythonパッケージのインストールは不要です。公開版に実使用・試験用の保存DBは含みません。

対応する[設計情報管理アプリ](https://github.com/ai-infra-data-lab/gas-turbine-design-manager)は別リポジトリです。現時点では独立して動作し、直接連携は今後実装する構成です。

## 起動

`start.bat` をダブルクリック。ブラウザに `http://127.0.0.1:8780/` が開きます。終了は起動ウィンドウでCtrl+C。別ポートは `python server.py --port 8781`。管理アプリの8770/8772とは別です。

## 機能

- 空気流量から出力を計算、目標正味発電出力から空気流量を逆算。
- 燃料質量の増加、吸気・燃焼器・排気の圧力損失、圧縮機・タービン等エントロピー効率、機械・発電機効率、固定電気補機を考慮。
- 全圧・全温・流量、取出し軸出力、正味発電、LHV熱効率、燃料流量、熱消費率、燃料消費率、質量・エネルギー収支を表示。
- 圧力比の設計点感度解析。基準点の空気流量を固定し、不成立点は理由付きで表示。オフデザイン解析ではない。
- 入力・結果JSON、状態表CSV、保存ケースの読込と比較。入力変更後は結果の保存・書出しを無効化。
- `data/cases.sqlite3` に明示保存。既存アプリ・管理DBは変更しない。

## 軸締結の概略強度設計（独立モジュール0.1）

画面上部「軸締結強度」または`http://127.0.0.1:8780/shaft-joints`。スプライン/カービックの平均歯面圧、歯元曲げ・せん断・相当応力、軸断面、ハブ周応力、カービックの分離力・保持締付力・ボルト群引張を評価。必要かみ合い長さ、必要組立締付力、現在条件の許容公称トルクを計算します。

`gt.mechanical.shaft_joint` / version 0.1.0 / schema 1。許容応力・材質/温度/根拠を入力する概略静強度モデル。AGMA/Gleasonの規格認証計算、局所接触FEA、疲労寿命は含みません。保存サイクルの軸位置を選び動力・回転数を取り込めます。ケースは`data/cases.shaft-joints.sqlite3`に独立保存。

[SHAFT_JOINTS.md](SHAFT_JOINTS.md)に理論・入力定義・数値サンプル・操作手順。`examples/joint_*`に基準内/超過/離間の仮定入力・結果を同梱。CLIは`python shaft_joints.py --kind curvic --output curvic-result.json`。

## 翼金属温度・冷却流量逆算・ポンピング（v0.6）

冷却流路ごとに熱抵抗（内外対流・金属・TBC）と等価並流LMTD熱交換を設定できます。指定流量から金属温度を計算し、1流路は許容翼温度から必要抽気率を逆算。熱伝達率・フィルム有効度は入力値です。ロータ冷却ポンピングは半径・旋回比・回転数によるEuler仕事と等価全圧効率で、空気の昇温/圧力上昇と軸動力消費へ反映します。

「翼熱・ポンピングサンプルを設定」→再計算→「冷却・流量収支」下部。730 Kへの逆算例、式・効率定義・適用範囲は[BLADE_COOLING.md](BLADE_COOLING.md)。局所3D翼温度や相対回復温度の計算は含みません。

## 冷却空気・抽気・混合（v0.5互換）

圧縮機段出口からの抽気を最大12流路でタービン要素間へ戻せます。入口空気基準の抽気率、供給流路圧損・外部熱、注入段/位置、混合圧損・必要圧力余裕・流速を入力。抽気後の圧縮機仕事、燃焼器流量、混合後組成/温度、タービン仕事を再計算します。

燃焼器出口/1段目ロータ入口の温度指定を選べます。冷却タービンの熱力学効率は単一入口ηttと別表示。NASA物性・タービン要素モードが必要です。翼熱・金属温度・ポンピングはv0.6の等価モデルで追加できます。冷却孔・回転流路の詳細は計算しません。

「冷却空気・抽気・混合」→「2段・2流路の冷却サンプルを設定」→再計算→「冷却・流量収支」で確認。[COOLING.md](COOLING.md)に計算定義・数値例・操作手順・制限を掲載。

`python cli.py --input examples/cooling_input.json --output result.json`

## 要素係数による詳細サイクル（v0.4互換）

圧縮機はインペラー・ディフューザー・リターンチャネル、タービンはノズル・ロータ・出口ディフューザーを各段に設定できます。Cp（静圧回復）またはζ（全圧損失）と出口流速を入力。NASA温度依存物性で全温/静温・全圧/静圧・密度・動圧・マッハ数を計算します。

要素モードは全体全圧比・対数段圧力配分を維持し、ロータ効率と静止要素損失から必要動力・実際の全体効率を再計算します。従来の全体効率欄は未使用。全体モードは従来どおりです。係数を形状から予測するミーンライン/CFDではありません。

[ELEMENTS.md](ELEMENTS.md)に係数定義・式・操作手順・2段の数値例・適用範囲を掲載。画面の「要素別性能・係数」→「2段の要素計算サンプルを設定」→再計算→「要素別性能」で確認できます。サンプルは操作説明用仮定・実機未検証です。

`python cli.py --input examples/elements_input.json --output result.json`

## 複数段の段間性能（全体モード・v0.3互換）

圧縮機・タービンを各1〜30段に配分し、「段間性能」で入口/出口全温・全圧、段圧力比、比仕事、動力、段等エントロピー効率、cp/γ、仕事・対数圧力配分を表示します。全体効率と端点を固定した一定ポリトロープ効率の経路上の配分です。

- 配分方法は「圧力比の対数」と「比仕事」。空欄は均等、任意の正の重みで前段/後段の配分を指定可能。
- 任意の段平均径と軸回転数からU・ψ=Δh/U²。径未指定時はnull。
- 4段圧縮機・3段タービンの操作例、段間CSV、保存・比較・JSON対応。
- 全体効率・サイクル出力は配分によって変えない。翼列損失・速度三角形・冷却・段間圧損・実機段性能を予測する機能ではない。

調査した理論、選定理由、式、操作手順、数値入り表、出典は[STAGING.md](STAGING.md)を参照。CLI例：`python cli.py --input examples/multistage_input.json --output result.json`。

## 計算モデル・操作

画面右上「操作・計算モデル」（`/guide`）に操作、数式、物性・損失の定義、一次資料、サンプル結果を掲載。

既定はNASA CEA公式データのNASA9多項式による温度依存理想気体です。N2・O2・Ar・CO2・H2Oのcp(T)、h(T)、エントロピー温度関数、cv、γを計算し、圧縮・膨張温度をエントロピーとエンタルピーから解きます。γを一定の指数に代入する近似ではありません。「物性・組成」で位置ごとの値と組成を確認できます。比熱一定の旧モデルも選べます。

燃料はメタン、GasTurb資料のGeneric（C86.08/H13.92質量%）、天然ガス組成（CH4 90/C2H6 10質量%）、任意C/H質量比。乾燥空気との希薄完全燃焼から組成を求め、圧縮・膨張中は組成を固定します。LHVは独立入力で、組成の選択によって自動変更しません。燃料298.15 K、各化学種の同温度の顕熱を0として、生成エンタルピーとLHVの二重計上を避けます。

GasTurbがNASA CEA由来の物性を利用することは[公式資料](https://www.gasturb.com/Downloads/Manuals/GasTurbDetails6.pdf)の2.1、2.2、2.5.7、5.1に記載されています。本アプリは同じNASA系の基礎データと凍結組成の考え方を採用しますが、GasTurb配布表の同一版・補間・化学平衡計算の再現ではなく、GasTurbとの数値一致は未検証です。

データはNASA公式`nasa/cea`のコミット`985fd33368b2334c4162a586c499e0ab41d12bd3`に固定。200–6000 Kの係数を同梱し外挿しません。サイクル入力の温度等にはさらに狭いソフト適用範囲があります。出典、抽出法、Apache-2.0のライセンス・NOTICEは`THIRD_PARTY.md`と`third_party/nasa_cea/`を参照。回転数は段平均径と組み合わせた負荷係数の算出に使用し、サイクル性能は変えません。

既定入力は検討用の仮定です。既定NASAモデル・メタン・1.2 kg/sでは正味発電約143.958 kW、効率約15.3316%（LHV）、燃料約67.6054 kg/h。旧比熱一定モデルでは約138.723 kW、14.2764%です。モデル内部の計算値であり、実機との相関は未検証です。管理アプリのサンプルにあった「100 kW」は要求値で、自動的にその出力になる条件ではありません。

再生、再熱、中間冷却、冷却抽気、湿度、化学平衡・解離、性能マップ、過渡、軸系マッチング、設計寸法は対象外。負の軸出力では発電機をモーターとして計算せず、発電関連値をnullとします。補機消費で正味出力が0以下の場合は効率等をnullにします。

## 将来の統合

`model.py` はSI入力定義、`engine.py` はUI・DBに依存しない純粋な計算、`server.py` はローカルUIアダプター。`engine.analyze(input)` または `engine.run_case(input)` を他アプリから利用できます。`INTEGRATION.md` を参照。

CLI例：

```powershell
python cli.py --input examples/nasa_methane_input.json --output result.json
python cli.py --input examples/nasa_target_100kw_input.json --output result-100kw.json
```

`--input` を省くと既定条件を計算します。結果JSONを入力に指定した場合も、入力を取り出して再計算します。

## 保存・検証

全ケースのバックアップは、終了後に `data/cases.sqlite3` をコピー。JSON・DBは暗号化していません。ケースは追加保存で既存の結果を上書きしません。

`python -m unittest -v test_cycle.py test_nasa.py test_stages.py test_elements.py test_cooling.py test_blade_cooling.py test_shaft_joints.py` で計算・保存・HTTPを検証します。HTTP接続は実行環境によって許可が必要な場合があります。NASA例は`examples/nasa_*`、旧schema 1の例は既存の`flow_*`と`target_100kw_*`です。schema 1の旧JSONは比熱一定、schema 2は元の物性モデルを維持して移行し、どちらも段構成は各1段になります。schema 3は段構成を維持し、schema 1〜3はいずれも要素モードなしで移行します。旧結果は再計算します。独立ライブラリCanteraによる照合記録は`reference/nasa9_cantera_validation.json`です。実施結果・画面確認の範囲は `VERIFICATION.md` を参照。

## 試験データ評価

サイクル画面上部「試験データ評価」から、UTF-8計測CSVの区間集計、運転条件での再計算、計測と計算の比較、計器・不確かさ・許容差・校正と検証の分離を扱えます。原CSVと結果を専用DBへ追記保存。数値入りの仮想試験を同梱しています。操作と制限は [TEST_EVALUATION.md](TEST_EVALUATION.md) を参照。
